# Bounded full-game Metal compiler follow-ups

Read-only investigation on 2026-10-23. No build or GPU execution was performed for this note. The seven-helper candidate used for inspection is `examples/survivors/dist/metal-experiments/run-20261023T180344Z-40471/generated.c` (SHA256 `97feec3655194fb5711411b2bf65f09e38f0104d8bcc7815e7504919f624c5c1`). These are proposed experiments, not successful compilation or correctness claims.

## Distinguish the two compilers

Apple describes source → Metal IR library → device-specific binary as separate stages. [`newLibraryWithSource:options:error:`](https://developer.apple.com/documentation/metal/metal-libraries) performs source-library work; archive/pipeline APIs subsequently need GPU-specific code. In the generated runtime, `gpu_make` creates a binary archive, calls `gpu_desc()` inside `addComputePipelineFunctionsWithDescriptor:`, and serializes it. `gpu_desc` calls `newLibraryWithSource`. `gpu_load` also calls `gpu_desc` before opening the archive. Therefore the existing `.gpu` archive path does not bypass source-library compilation. Timestamp both boundaries before attributing a timeout to either compiler.

This is actual evidence that source-library compilation was spending that interval in inlining cost analysis; it is stronger than a static source-size hypothesis. Both size optimization and broader noinline boundaries target this observed work; size optimization remains the smaller first change.

## Ranked follow-ups after stage tracing

1. **Set size optimization, preserve safe math.** Insert `opts.optimizationLevel = MTLLibraryOptimizationLevelSize;` beside `opts.mathMode = MTLMathModeSafe;` in `gpu_desc`. This changes one host compiler setting, retaining the game, scheduling and arithmetic policy. [Apple's size-optimization guidance](https://developer.apple.com/documentation/metal/minimizing-the-binary-size-of-a-shader-library) says the option limits code duplication from inlining/unrolling and can shorten compilation. That is a rationale, not evidence this game will fit 120 seconds. The installed macOS 27 SDK's `Metal.framework/Headers/MTLLibrary.h` declares the property and enum, available since macOS 13. Compare to the traced seven-helper candidate, altering only this setting. Compile success must precede exact CPU/GPU comparisons.

2. **Make every remaining generated spin helper device-noinline.** The inspected candidate has 717 `INLINE Term spin_N` and 43 `DFAR Term spin_N` definitions. The seven-helper transformation moved seven of the original 724 INLINE helpers. `DFAR` is existing runtime machinery: device `FAR` is `static __attribute__((noinline))`; host `DFAR` expands back to `INLINE`. Replacing only the 717 definition prefixes is a mechanically auditable experiment: preserve bodies, order, calls and CPU preprocessed code. It tests whether remaining cross-helper expansion prevents compilation. It may increase device calls, stack demand or execution time; retaining safe math is insufficient to claim parity without execution. Existing noinline helpers establish syntax precedent, not scalability. Test independently from size optimization if attribution matters.

3. **Use offline compilation as a diagnostic, not an automatic fix.** `xcrun --find metal` locates the installed Metal toolchain. Apple documents [source → IR → metallib commands](https://developer.apple.com/documentation/metal/building-a-shader-library-by-precompiling-source-files) and runtime loading with `newLibraryWithURL:error:`. This can separate frontend/IR compilation from archive code generation and makes the compiler an owned process. Preserve the exact `CUBE_LOG`, Metal language revision and safe math (`-fmetal-math-mode=safe`; the local compiler's `--help` explicitly says its default is fast). A `.metallib` IR library is not the runtime's `.gpu` binary archive. To bypass `gpu_desc` source compilation, the runtime must actually load the IR library by URL; dropping an IR file at the archive path will not do it. Offline compilation moves work, but does not prove that work becomes faster.

4. **Split device work-loop segments only if smaller changes fail.** Device `work_loop` currently contains 1073 `WL_CASE` segments in one switch and an 87-Term register bank (`r0`…`r85`, plus `rp`). The host already uses separate functions, but its `musttail` calls and function-pointer table cannot simply replace the device switch. Device transitions mutate `fid`, `rn`, `sp` and the register bank; `WL_RETN` changes both result count and stack before dispatch. A correct extraction needs an explicit shared state/result protocol and must preserve stack spills, returns, polling and errors. This is a compiler-backend change with a larger semantic review surface, not a small local game fix. Large source size alone does not establish it is necessary or would succeed.

Keep the existing 120-second Metal build maximum. After a timeout, preserve the trace and inspect bounded process evidence before another distinct candidate; never kill all system compiler services. None of these proposals establishes impossibility of the game on Metal, nor guarantees a feasible build. A passing build still needs forced GPU execution, gameplay-summary parity, and separately labeled timing; full-state equivalence remains a different qualification.

## If all-spin noinline still fails: mechanical segment extraction

The parent reports that the traced seven-helper build completed library creation in 89.331 seconds and then timed out in archive-add within the remaining 120-second total budget; size optimization completed library creation in 93.485 seconds and also timed out in archive-add. These observations do not isolate all archive time or establish a benefit from size mode. The next all-spin noinline trial is separate.

A more exact source count matters here: of the 1073 textual `WL_CASE` occurrences, 102 are already inside `#if !DEVICE`, leaving **971 device-active cases**, including runtime entry/exit/apply cases. The previously recorded 968 solve-reachable cases describe a different set. Removing the already guarded CPU cases cannot shrink the device control-flow graph. Preserve FID numbers and `FID_T` layout; renumbering is unnecessary and would enlarge the change.

If process samples implicate work-loop optimization after all spins are noinline, a viable diagnostic is an ordinary-function trampoline, using the following mechanical contract. This is a proposed transformation, not implemented or verified here.

1. Keep the original host preprocessor branch byte-equivalent. Wrap only a new device implementation in `#if DEVICE`, with the original host implementation in the corresponding `#else`. Duplicate segment text mechanically; retain each existing `#if !DEVICE` guard so CPU-only segments disappear from the new device side too.
2. Define a lane-private `WlState` with `DEV Term* qsp`, `u32 qseq, qrn, qfid, qpoll`, `Term result`, and named bank fields `v0`…`v85`, `vp`. Do not put this state in shared/device memory. Original `Env e` can remain a by-value argument: the inspected segment bodies never assign to `e` or an `e` field.
3. After the existing spin helper definitions **and `lane_spill` definition**, alias `sp`, `seq`, `rn`, `fid`, `wpoll`, `r0`…`r85`, `rp` to `s->qsp`, `s->qseq`, etc. Use different field names to avoid aliases expanding again inside field references. Undefine every alias before the outer dispatcher and subsequent runtime code.
4. Change device `WL_CASE(F)` to `FAR bool segment_##F(Env e, THR WlState* s) {`, keeping `WL_OPEN {` and the two closing braces of each segment unchanged. The inspected bodies have no literal `break`, `goto`, or labels, no local declarations colliding with the state aliases, and no local `wpoll` declaration. Segment-local `WL_SPIN` loops retain their current polling and `WL_AGAIN(F)` remains `continue`.
5. Give segment functions two exit meanings. `WL_JMP(F)` sets the shared `fid` and returns `false`: dispatch another segment. Every literal `return EXPR;` in a segment becomes `return wl_done(s, EXPR);`, where `wl_done` stores `result` and returns `true`: finish the original work_loop with exactly that Term. Parse or strictly whitelist the return syntax rather than replacing text in comments/strings. `WL_DYN` follows `WL_JMP`. **Also override `WL_ROOM` and `WL_SPIN`: their embedded `return 0` must use `wl_done(s,0)`**, preserving error posting/polling. All stack/register macros (`WL_RETN`, `WL_FRAME`, `WL_ARGS`, `WL_LOAD`, `WL_SAVE`, `WL_TAKE`, `WL_LAST`) then operate on the shared aliased state.
6. The outer `work_loop(e,sp,t,seq)` initializes qsp/qseq/qrn/qfid/qpoll exactly as before and `v0=t`. Its original top-level polling loop switches on qfid and invokes the corresponding named segment function. If that function returns true, return `state.result`; otherwise repeat the dispatcher. The unknown-FID default still posts `ERR_FIDS` and returns zero. Calls are direct and nonrecursive; do not introduce function pointers or reuse host `musttail` machinery. Ensure each emitted dispatcher case has the same device guard as its helper definition.

This bounds each segment's optimizer-visible control-flow graph and prevents the compiler merging segments back when `FAR` is honored. The original switch has jumps from many segments through one shared dispatcher and a large live register bank; block-frequency/branch-probability analysis can still traverse that graph even when spin calls are noinline. That is a plausible mechanism, **not** an observed cause unless a new sample identifies it.

The state pointer can force register-bank spills into thread memory, and hundreds of calls can slow execution. Exact device summary parity and bounded execution remain required even if compilation improves. Qualify the transformation first on arithmetic and raw-column controls, validate CPU preprocessed bytes against the untransformed source, and assert that no function body, FID mapping, safe-math setting, scheduling constant, or error exit changes beyond the stated state-transfer rewrite. Any residual unclassified return/transition should stop transformation rather than guess.

Further extraction audit: the segment text contains exactly 45 `WL_SPIN` / 45 `WL_SPUN` pairs and 53 `WL_AGAIN` occurrences. Every `WL_AGAIN` is inside its segment-local loop (depth one); none targets the outer work-loop directly. **Override `WL_SPUN` to `} return false;`** in the split implementation: its original `} break;` exits the device switch and is invalid after extraction. Preserve `WL_AGAIN` as local `continue`. A CPU diagnostic switch such as `BEND_SEGMENT_CPU_CHECK` can execute the extracted state machine with host lane stride and scheduling branches for parity checks; it must skip or replace the whole host-only `// Work` macro override block, not only the `wl_tab` declarations, because that block empties `WL_SPIN`/`WL_SPUN` and changes `WL_AGAIN` to a tail dispatch. Ordinary host compilation must still preprocess identically to the original.

Read-only review of the subsequently implemented `tools/survivors-bot/metal_segments.py`: no concrete state-transfer or dispatch bug was identified. It retains qsp/qseq/qrn/qfid/qpoll and all 87 registers, converts literal terminal returns and embedded polling/room failures into `metal_done`, makes `WL_JMP` request the next segment, preserves local `WL_AGAIN` loops, and reproduces availability guards in the dispatcher. Its CPU-check mode skips the complete host override block, including the host tail-dispatch loop macros. After the transformed work-loop, remaining runtime text references only `WL_RESW`, so the changed segment macros do not affect later functions. This source review does not qualify compilation or runtime parity; those require the parent's separate checks.

The all-spin noinline trial reportedly completed library creation in 107.757 seconds, leaving roughly 12 seconds before archive-add hit the same total 120-second cap. This does not show that noinline improved compilation; compare it only as a distinct failed feasibility candidate. The next split candidate addresses a different optimizer boundary.
