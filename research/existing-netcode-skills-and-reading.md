# Existing skills in gaming netcode and what to read

Retrieved October 25, 2026. Read only local directories, GitHub API and `SKILL.md`/references/examples themselves. Nothing was installed, external instructions and scripts were not executed. This is the search for materials; hit correction is performed separately.

## Search result

**Yes, skills specifically for prediction/reconciliation and game clocks already exist.** I found several direct matches on the topic and read the source files. However, in the materials reviewed, one ready-made skill was not found that simultaneously covers in detail browser clock domains, ACK of executed input, predicted spawn matching, agreed upon time of interacting objects, correction convergence and contact checking. This is the limit of this search, not a statement that such a skill does not exist anywhere.

For our example, it is most useful to read **SS14 Prediction as a specific ECS practice**, **Gambetta as an explanation of the protocol**, **Unity Netcode for Entities as a handbook of complex interactions**. The existence of the beautifully named `multiplayer-netcode` does not mean that its examples have already passed our tests.

## What to read: shortcut

1. **Gabriel Gambetta - Client-Side Prediction and Server Reconciliation.** Start here: the author literally shows jumping back/forward after server snapshots, then enters the sequence and confirmation of the last input processed. After the chapter, it should be clear why the receive packet ACK is not sufficient. [Original chapter](https://www.gabrielgambetta.com/client-side-prediction-server-reconciliation.html); then [Entity Interpolation](https://www.gabrielgambetta.com/entity-interpolation.html).
2. **Glenn Fiedler — Fix Your Timestep!** Read about the accumulator, separating rendering from simulation and the spiral of death. This is the foundation of time handling; it does not define network ACK semantics. [Original](https://gafferongames.com/post/fix_your_timestep/). For the network part, continue [Networked Physics](https://gafferongames.com/post/networked_physics_2004/) and [Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/), taking into account the historical context of transport recommendations.
3. **Unity Netcode for Entities - specifically difficult cases.** For our current bug, the most important thing is [Prediction edge cases / partial snapshots](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction-details.html#possible-mitigations): what errors appear when interacting entities are simulated from different states. Next [Prediction smoothing](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction-smoothing.html): correction should eliminate the discrepancy. Then [Predicted spawn classification](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/ghost-spawning.html#ghost-classification-and-entity-matching): why one spawn tick is not enough for several bullets of the same type.
4. **SS14 Prediction - read one real ECS playbook in its entirety.** Complete `CurTick / LastRealTick / LastProcessedTick`, rollback of network fields, general simulation and `IsFirstTimePredicted`. It is especially useful to compare with our division of canonical state and presentation. [Read skill](https://github.com/makura-games/sunrise-station/blob/e384ec9782b658c67876170ffd22964b1bcb7f24/.agents/skills/ss14-prediction/SKILL.md).
5. **Lightyear - move from concepts to library implementation.** View [simple_box](https://github.com/cBournhonesque/lightyear/tree/main/examples/simple_box), then input/prediction/interpolation crates. [README](https://github.com/cBournhonesque/lightyear#features) describes per-tick input and packet loss protection; [the book by ](https://cbournhonesque.github.io/lightyear/book/) is clearly marked as incomplete working notes, so check it against the current API and sources. This is a Bevy stack and an architecture comparison material, not a drop-in module of our Bend World.

Two additional primary sources for point-by-point analysis:

- **Yahn Bernier / Valve - Latency Compensating Methods in Client/Server In-game Protocol Design and Optimization.** Carefully read the input command, shared movement/weapon code and replay effects. The document has a command duration: one common fixed tick is a useful way to specify a uniform step, but is not the only historical form of contract. [Author's technical document, PDF copy](https://www.gamedevs.org/uploads/latency-compensation-in-client-server-protocols.pdf). [Half-Life weapon prediction source](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/hl/hl_weapons.cpp) is useful for reading the implementation; its header contains separate terms of use.
- **Web timing - read the required specification items.** [High Resolution Time: `now()`](https://www.w3.org/TR/hr-time-3/#now-method), [time origins](https://www.w3.org/TR/hr-time-3/#sec-time-origin), [HTML: animation frame callbacks](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#run-the-animation-frame-callbacks). The monotony of the clock source does not make the arbitrary order of timestamps already taken and later delivered monotonous. This is a derivation from API contracts; comparison of different relative time origins requires an explicit conversion.

## What to take into our skill

Transfer verifiable solutions and links, rather than ready-made foreign texts: number and duration/tick of the executed input; one owner accumulator; explicit clock domains; logical life of an entity separate from the pool slot; general contact timeline; canonical convergence is separate from presentation continuity; one-time replay effects; red tests of the entire trajectory and the actual delay of the meter.

The skills found show that these are established patterns. Reading them should precede choosing a model; The presence of a skill in itself does not prove that a particular prediction/interpolation mixture is consistent. For our contact bug, detailed Unity sections and real regression frames are more important than another general list of tips.
