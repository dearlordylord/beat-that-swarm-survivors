# Существующие скиллы по игровому netcode и что читать

Проверено 25 октября 2026. Только чтение локальных каталогов, GitHub API и самих `SKILL.md`/references/примеров. Ничего не установлено, внешние инструкции и скрипты не исполнялись. Это поиск материалов; исправление попаданий выполняется отдельно.

## Результат поиска

**Да, скиллы именно по prediction/reconciliation и игровым часам уже существуют.** Нашёл несколько прямых совпадений по теме и прочитал исходные файлы. Однако в просмотренных материалах не найден один готовый скилл, который одновременно подробно закрывает browser clock domains, ACK исполненного ввода, predicted spawn matching, согласованное время взаимодействующих объектов, сходимость коррекции и проверку контактов. Это граница данного поиска, не утверждение, что такого скилла нигде нет.

Для нашего примера полезнее всего читать **SS14 Prediction как конкретную ECS-практику**, **Gambetta как объяснение протокола**, **Unity Netcode for Entities как handbook сложных взаимодействий**. Существование красиво названного `multiplayer-netcode` не означает, что его примеры уже выдержали наши проверки.

## Где искал и чего не подтверждаю

- Просмотренный локальный каталог `~/.codex/skills`: готовый специализированный netcode-скилл не найден. Общие proof/property-testing навыки не считаются заменой сетевого дизайна. Создаваемый нами `skills/realtime-netcode/` — отдельная работа, а не найденный внешний скилл.
- Официальный [каталог openai/skills `.curated`](https://api.github.com/repos/openai/skills/contents/skills/.curated): на проверенном head `49f948faa9258a0c61caceaf225e179651397431` содержит 39 записей, без игрового multiplayer/netcode-скилла. Путь `.experimental` вернул 404; API каталога `skills` показал `.curated` и `.system`.
- Открытый GitHub-поиск по `SKILL.md`, `netcode`, `prediction`, `reconciliation`, `fixed timestep`; затем чтение самих файлов и доступных references. Поисковые агрегаторы использовались лишь как указатели, не как подтверждение содержания.
- Найденный в поиске `zeroLR/skills/skills/game-loop/SKILL.md` по raw URL вернул 404: он не включён в список проверенных рекомендаций.
- Не проверены все репозитории, все ветки, история каждого скилла и корректность каждого примера. Ни один найденный скилл не устанавливался.

## Что читать: короткий путь

1. **Gabriel Gambetta — Client-Side Prediction and Server Reconciliation.** Начать здесь: автор буквально показывает прыжки назад/вперёд после серверных снимков, затем вводит sequence и подтверждение последнего обработанного ввода. После главы должно быть понятно, почему ACK получения пакета недостаточен. [Оригинальная глава](https://www.gabrielgambetta.com/client-side-prediction-server-reconciliation.html); затем [Entity Interpolation](https://www.gabrielgambetta.com/entity-interpolation.html).
2. **Glenn Fiedler — Fix Your Timestep!** Прочитать accumulator, отделение rendering от simulation и spiral of death. Это основа работы времени; она не задаёт сетевую семантику ACK. [Оригинал](https://gafferongames.com/post/fix_your_timestep/). Для сетевой части продолжить [Networked Physics](https://gafferongames.com/post/networked_physics_2004/) и [Snapshot Interpolation](https://gafferongames.com/post/snapshot_interpolation/), учитывая исторический контекст транспортных рекомендаций.
3. **Unity Netcode for Entities — конкретно сложные случаи.** Для нашей нынешней ошибки важнее всего [Prediction edge cases / partial snapshots](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction-details.html#possible-mitigations): какие ошибки появляются, когда взаимодействующие сущности симулируются из разных состояний. Следом [Prediction smoothing](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction-smoothing.html): коррекция должна устранять расхождение. Затем [Predicted spawn classification](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/ghost-spawning.html#ghost-classification-and-entity-matching): почему одного spawn tick недостаточно для нескольких пуль одного типа.
4. **SS14 Prediction — прочитать один настоящий ECS-playbook целиком.** Пройти `CurTick / LastRealTick / LastProcessedTick`, rollback сетевых полей, общую симуляцию и `IsFirstTimePredicted`. Особенно полезно сопоставить с нашим разделением canonical state и presentation. [Прочитанный скилл](https://github.com/makura-games/sunrise-station/blob/e384ec9782b658c67876170ffd22964b1bcb7f24/.agents/skills/ss14-prediction/SKILL.md).
5. **Lightyear — перейти от понятий к библиотечной реализации.** Посмотреть [simple_box](https://github.com/cBournhonesque/lightyear/tree/main/examples/simple_box), затем input/prediction/interpolation crates. [README](https://github.com/cBournhonesque/lightyear#features) описывает per-tick ввод и защиту от потери пакетов; [книга автора](https://cbournhonesque.github.io/lightyear/book/) прямо обозначена как неполные рабочие заметки, поэтому сверять её с текущим API и исходниками. Это Bevy-стек и материал для сравнения архитектуры, не drop-in модуль нашего Bend World.

Два дополнительных первоисточника для точечного разбора:

- **Yahn Bernier / Valve — Latency Compensating Methods in Client/Server In-game Protocol Design and Optimization.** Внимательно читать команду ввода, разделённый общий код движения/оружия и replay effects. В документе есть длительность команды: один общий фиксированный tick — полезный способ задать одинаковый шаг, но не единственная историческая форма контракта. [Авторский технический документ, PDF-копия](https://www.gamedevs.org/uploads/latency-compensation-in-client-server-protocols.pdf). [Half-Life weapon prediction source](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/hl/hl_weapons.cpp) полезен для чтения реализации; его заголовок содержит отдельные условия использования.
- **Web timing — читать нужные пункты спецификаций.** [High Resolution Time: `now()`](https://www.w3.org/TR/hr-time-3/#now-method), [time origins](https://www.w3.org/TR/hr-time-3/#sec-time-origin), [HTML: animation frame callbacks](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#run-the-animation-frame-callbacks). Монотонность источника часов не делает монотонным произвольный порядок уже снятых и позже доставленных timestamps. Это вывод из контрактов API; сравнение разных relative time origins требует явного преобразования.

## Что брать в наш скилл

Перенести проверяемые решения и ссылки, а не готовые чужие тексты: номер и длительность/тик исполненного ввода; один владелец accumulator; явные clock domains; логическая жизнь сущности отдельно от pool slot; общий timeline контакта; canonical convergence отдельно от presentation continuity; однократные эффекты replay; red-тесты всей траектории и фактической задержки измерителя.

Найденные скиллы показывают, что это устоявшиеся паттерны. Их чтение должно предшествовать выбору модели; наличие скилла само по себе не доказывает, что конкретная смесь prediction/interpolation согласована. Для нашего контактного бага подробные Unity-разделы и реальные регрессионные кадры важнее ещё одного общего списка советов.
