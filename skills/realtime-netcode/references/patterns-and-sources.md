# Patterns and primary sources

Use these as architectural references; verify the current documentation and source of a library before integrating it. The linked engine implementations require their own simulation contracts and are not automatically compatible with another ECS or language.

| Topic | Primary reference | What to take from it |
| --- | --- | --- |
| Fixed simulation step | [Glenn Fiedler: Fix Your Timestep!](https://gafferongames.com/post/fix_your_timestep/) | Accumulated elapsed time, fixed steps, rendering interpolation and bounded catch-up. It does not define input ACK semantics. |
| Input prediction and reconciliation | [Gabriel Gambetta: Client-Side Prediction and Server Reconciliation](https://www.gabrielgambetta.com/client-side-prediction-server-reconciliation.html) | Number commands, return the last processed input, replay the unprocessed suffix; the article illustrates backward/forward correction jumps. |
| Practical shared weapon prediction | [Valve Half-Life weapon prediction source](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/hl/hl_weapons.cpp), [Source SDK prediction](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/prediction.cpp) | Shared simulation, command history and first-run versus replayed effects. Review licenses before copying code. |
| Monotonic browser time | [W3C High Resolution Time: now](https://www.w3.org/TR/hr-time-3/#now-method), [time origins](https://www.w3.org/TR/hr-time-3/#sec-time-origin), [WHATWG animation callbacks](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#run-the-animation-frame-callbacks) | Chronological `performance.now()` readings share a monotonic source; callbacks can consume previously sampled timestamps. Window and Worker relative timestamps have distinct origins. A single accumulator owner and explicit domains are design choices built on these semantics. |
| Predicted spawning and matching | [Unity Netcode for Entities: ghost spawning](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/ghost-spawning.html#ghost-classification-and-entity-matching) | Classify predicted spawns and match them to authority. The documented tick-window matching has limits, including multiple bullets in one tick and batching differences. |
| Interacting prediction timelines | [Unity NFE prediction edge cases](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction-details.html#possible-mitigations) | Partial rollback or snapshots can simulate some interacting objects while others remain at another time; use a coherent interaction policy and an explicit correction path. |
| Correction and collision history | [Unity NFE prediction smoothing](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction-smoothing.html), [physics and lag compensation](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/physics.html#using-lag-compensation-predicted-collision-worlds) | Correct the error toward canonical state; separate render smoothing from collision truth and explicit historical collision-world queries. |

## Library boundaries

- [Lightyear](https://github.com/cBournhonesque/lightyear) and its [book](https://cbournhonesque.github.io/lightyear/book/) provide a Bevy-oriented prediction/replication model. Inspect its input timeline, predicted components and [pre-spawn API](https://docs.rs/lightyear_replication/latest/lightyear_replication/) when comparing contracts. The book is not a substitute for current API/source behavior.
- [Bevy Replicon](https://github.com/simgine/bevy_replicon) supplies server-authoritative ECS replication; prediction/interpolation are listed separately in its ecosystem. Identify the additional layer before attributing guarantees to replication alone.
- [Unity Netcode for Entities](https://docs.unity3d.com/Packages/com.unity.netcode@1.10/manual/prediction.html) owns prediction scheduling inside Unity ECS. Its handbook can inform another engine without requiring a migration.
- [GGPO](https://github.com/pond3r/ggpo) and [GGRS](https://docs.rs/ggrs/latest/ggrs/#how-it-works) are rollback approaches requiring game-state save/load/advance and repeatable simulation. Evaluate that integration contract when full rollback is in scope; it is larger than replacing a clock or transport.
- [Iroh protocols](https://docs.iroh.computer/concepts/protocols) describe application protocols over connections. Input IDs, execution ACKs, simulation time and presentation remain application-level decisions.

Choose the smallest architecture that satisfies the declared interactions. Owner-only prediction can work for movement with limited dependencies; combat prediction must account for the states used by its contacts. Authoritative playback with local anticipation is another valid choice. Neither a new transport nor an unbounded visual-history cache establishes that contract.
